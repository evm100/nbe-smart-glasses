Adding a new sensor

The board describes it. The firmware declares the new stream — its name, channels and units — when it starts. Nothing has to be changed on this website to record it. (Firmware: copy xstream_template.c; format in firmware/PROTOCOL.md, “Protocol v2.1”.)
It shows up by itself. During a recording the new values appear under “Other sensors” on the live page; afterwards on the session page, on the same time axis as pulse and eye.
Give it a name here. Add a short entry to config/sensors.toml so it gets a proper name, family and status on this page.

Where the computing happens

Today the glasses send raw data (every pulse sample, every camera frame) and the server does the analysis. That keeps everything re-analysable — any improvement to a method can be re-run on all old recordings — but sending raw video costs battery.

The next step is to compute on the glasses and send only the results. The platform is prepared for both at once: a board can send a stream of results it computed itself next to (later: instead of) the raw stream, labelled with the method and its version. The server stores both the same way, so they can be compared before raw transmission is switched off. The first such stream — per-frame brightness, contrast and motion from the eye camera — is in the firmware (off by default until tested on a board) and in the simulator.

This page is drawn from config/sensors.toml. Statuses are set by hand there — keep them honest.
